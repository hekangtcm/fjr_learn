# Release Plan

> 灰度发布计划：BookNest Mini Pro 首个体验版 → 审核 → 灰度 → 全量。

## 版本信息

| 项目 | 内容 |
|---|---|
| 版本 | 0.1.0 |
| 类型 | BookNest Mini Pro 首个体验版 |
| 后端版本 | 同分支 feat/day12-18-mini-pro |
| 小程序版本 | 0.1.0 |
| 发布时间 | Day 18 完成 CI 后 |

## 发布策略

1. **CI 上传体验版**
   - GitHub Actions 触发 `mini-program.yml`。
   - 生成体验版，管理员和体验成员可访问。

2. **内部验收通过**
   - 按 `TRIAL_ACCEPTANCE_CHECKLIST.md` 逐项验证。
   - 开发团队、PM、QA 参与验收。

3. **提交审核**
   - 在微信公众平台 → 版本管理 → 提交审核。
   - 附测试说明：微信登录即可体验，无需额外账号。
   - 确保所有审核资料已准备（隐私协议、用户协议、功能说明）。

4. **审核通过后先小比例灰度发布**
   - 首次发布：1% 或 100 个用户。
   - 观察 24 小时，无严重问题后扩大比例。

5. **观察关键指标**
   - 登录成功率、支付成功率、API 5xx 率、内容安全误杀率。

6. **无严重问题后扩大比例**
   - 10% → 50% → 100%（全量）。
   - 每阶段观察至少 24 小时。

7. **最终全量发布**
   - 确认所有指标正常后，全量发布。

## 观察指标

| 指标 | 阈值 | 处理方式 |
|---|---|---|
| 登录失败率 | > 5% | 暂停放量，检查微信登录配置 |
| 支付失败率 | > 5% | 检查微信支付和回调链路 |
| API 5xx 率 | > 1% | 回滚后端或小程序版本 |
| 上传失败率 | > 5% | 检查 OSS 和合法域名配置 |
| 内容安全误杀投诉 | 明显升高 | 调整 REVIEW 策略，降低误杀率 |
| 小程序崩溃率 | > 1% | 回滚版本，分析日志 |
| 首屏时间 | > 3s | 检查分包和图片加载 |

## 发布前确认

- [ ] 后端生产数据库已备份。
- [ ] 后端日志可查看（Winston / AuditLog）。
- [ ] 小程序体验版验收通过（`TRIAL_ACCEPTANCE_CHECKLIST.md`）。
- [ ] 审核检查清单通过（`WECHAT_REVIEW_CHECKLIST.md`）。
- [ ] 客服入口可用，客服响应机制已就绪。
- [ ] 回滚方案已确认（`ROLLBACK_PLAN.md`）。
- [ ] 灰度发布指标和观察计划已就绪。
- [ ] 紧急关闭开关已配置（见 `ROLLBACK_PLAN.md`）。

## 发布节奏

| 阶段 | 时间 | 比例 | 决策 |
|---|---|---|---|
| 体验版 | Day 18 | 内部 | 验收通过后提交审核 |
| 审核 | 1-3 天 | 0% | 等待微信审核结果 |
| 灰度 1 | 审核通过 + 24h | 1% | 观察登录、支付、内容安全 |
| 灰度 2 | 灰度 1 + 24h | 10% | 扩大用户范围 |
| 灰度 3 | 灰度 2 + 24h | 50% | 接近全量 |
| 全量 | 灰度 3 + 24h | 100% | 正式发布 |

## 紧急停止条件

以下任一情况触发紧急停止，回滚到上一稳定版本：

1. 登录失败率 > 10%
2. 支付失败率 > 10%
3. API 5xx 率 > 5%
4. 小程序崩溃率 > 3%
5. 内容安全误杀率 > 20%
6. 收到用户严重投诉（如隐私泄露、数据丢失）
